평균 실행시간 = 각 반복에서 측정한 실행시간의 합 / 반복 횟수

예를 들어 실제로 5회 측정했다면:

평균 = (1회 + 2회 + 3회 + 4회 + 5회) / 5

Colab 셀 4 — 실제 실행시간 측정 

for size in data_sizes:

    for repeat in range(repeat_count):

        # 무작위 정수 데이터 생성
        original = [
            random.randint(1, 100000)
            for i in range(size)
        ]

        # -------------------------
        # 1. 버블 정렬
        # -------------------------

        data = original.copy()

        start = time.perf_counter()

        for i in range(len(data) - 1):
            for j in range(len(data) - 1 - i):
                if data[j] > data[j + 1]:
                    data[j], data[j + 1] = data[j + 1], data[j]

        end = time.perf_counter()

        bubble_time = end - start

        results.append([
            size,
            repeat + 1,
            '버블 정렬',
            bubble_time
        ])

        # -------------------------
        # 2. 선택 정렬
        # -------------------------

        data = original.copy()

        start = time.perf_counter()

        for i in range(len(data) - 1):

            min_index = i

            for j in range(i + 1, len(data)):
                if data[j] < data[min_index]:
                    min_index = j

            data[i], data[min_index] = data[min_index], data[i]

        end = time.perf_counter()

        selection_time = end - start

        results.append([
            size,
            repeat + 1,
            '선택 정렬',
            selection_time
        ])

        # -------------------------
        # 3. 삽입 정렬
        # -------------------------

        data = original.copy()

        start = time.perf_counter()

        for i in range(1, len(data)):

            key = data[i]
            j = i - 1

            while j >= 0 and data[j] > key:
                data[j + 1] = data[j]
                j -= 1

            data[j + 1] = key

        end = time.perf_counter()

        insertion_time = end - start

        results.append([
            size,
            repeat + 1,
            '삽입 정렬',
            insertion_time
        ])

이 코드에서 중요한 점은 각 반복에서 original이라는 데이터 하나를 만든 뒤

1. 탐구 동기 및 목적

정보 수업에서 알고리즘은 같은 문제를 해결하더라도 해결 절차에 따라 효율이 달라질 수 있다는 점을 학습하였다. 특히 컴퓨터 프로그램에서는 처리해야 할 데이터가 많아질수록 알고리즘의 효율이 프로그램의 성능에 중요한 영향을 줄 수 있다고 생각하였다.

이에 동일한 정렬 문제를 해결하는 버블 정렬, 선택 정렬, 삽입 정렬을 Python으로 직접 구현하고, 정렬할 데이터의 개수를 변화시키면서 실제 실행시간을 측정하고자 하였다.

이를 통해 데이터 규모가 증가할 때 세 정렬 알고리즘의 실행시간 차이가 어떻게 변화하는지 분석하고, 알고리즘의 구조와 프로그램 처리 성능 사이의 관계를 이해하는 것을 탐구 목적으로 설정하였다.

2. 연구문제와 가설

연구문제

정렬할 데이터의 개수가 증가할수록 버블 정렬, 선택 정렬, 삽입 정렬의 실행시간 차이는 어떻게 달라지는가?

가설

정렬할 데이터의 개수가 증가하면 세 정렬 알고리즘의 실행시간도 증가할 것으로 예상하였다.

또한 세 알고리즘은 데이터를 비교하고 이동시키는 방법이 서로 다르므로 데이터의 개수가 많아질수록 실제 실행시간에서도 차이가 나타날 가능성이 있다고 예상하였다.

다만 실제 실행시간은 프로그램 구현 방식과 실행환경의 영향도 받을 수 있으므로 직접 반복 측정한 결과를 통해 확인하기로 하였다.

3. 이론적 배경

정렬 알고리즘은 여러 데이터를 일정한 기준에 따라 순서대로 배치하는 절차이다. 이번 탐구에서는 버블 정렬, 선택 정렬, 삽입 정렬을 비교한다.

버블 정렬은 서로 인접한 두 값을 비교하여 순서가 맞지 않을 경우 위치를 교환하는 과정을 반복한다.

선택 정렬은 정렬되지 않은 부분에서 가장 작은 값을 찾아 현재 위치의 값과 교환하는 과정을 반복한다.

삽입 정렬은 앞부분의 데이터가 이미 정렬되어 있다고 보고 새로운 값을 알맞은 위치에 삽입하는 방법이다.

기본적인 형태의 세 알고리즘은 데이터 개수를 n이라고 할 때 대표적으로 O(n²)의 시간복잡도를 갖는 정렬 방법으로 설명할 수 있다.

그러나 시간복잡도가 같다고 해서 실제 실행시간이 항상 동일한 것은 아니다.

알고리즘마다 실제 비교 횟수와 값 이동 방식이 다르고, 입력 데이터의 상태, Python 코드 구조, 컴퓨터 실행환경 등의 영향을 받을 수 있기 때문이다.

후속 탐구로 입력 데이터의 정렬 상태와 비교·이동 횟수를 추가하여 알고리즘의 실제 성능 차이가 발생하는 원인을 분석하고자 하는 확장성을 보임.

2. 탐구보고서 내용과 세특 반영 연결

반영 요소 실제 탐구에서 확인되는 내용 세특에 반영되는 강점
연구문제 데이터 개수가 증가할수록 버블·선택·삽입 정렬의 실행시간 차이가 어떻게 변하는지 탐구 명확한 비교·변화형 연구문제 설정
교과 개념 알고리즘, 리스트, 반복문, 조건문, 프로그램 실행시간 정보 교과 개념의 실제 적용
공학 원리 데이터 규모와 알고리즘 처리 효율의 관계 컴퓨터공학의 성능·효율 관점
탐구 방법 Python으로 세 정렬 알고리즘 직접 구현 단순 조사보다 실제 코딩 수행이 드러남
변수·설계 조건 데이터 개수를 100, 500, 1000, 2000, 3000으로 변화 독립변인을 명확하게 설정함
통제 조건 같은 원본 데이터를 복사하여 세 알고리즘에 적용 공정한 성능 비교를 위한 조건 통제
측정·데이터 각 조건을 10회 반복하고 실행시간 측정 반복 측정에 기반한 정량적 탐구
계산 10회 실행시간의 평균, 알고리즘 간 실행시간 차이·배수 비교 측정값을 계산하여 근거화함
코드 과정 버블·선택·삽입 정렬 구현, time.perf_counter()를 이용한 실행시간 측정 코딩과 성능 측정의 연결
성능 평가 평균 실행시간을 기준으로 비교 프로그램을 작동 여부가 아닌 성능으로 평가
오류·오차 Colab 실행환경에 따라 시간이 달라질 수 있음을 고려 측정 결과의 한계를 인식함
수정·대응 행동 1회 결과 대신 조건별 10회 반복 후 평균 사용, 동일 데이터 적용 문제를 발견하고 측정방법을 개선함
결과 3000개에서 버블 1.459649초, 삽입 0.747394초, 선택 0.694219초. 버블-선택 차이는 약 0.765430초 실제 수치에 근거한 분석
진로 연결 데이터 규모가 커질수록 알고리즘 선택이 프로그램 성능에 중요함을 확인 컴퓨터계열 진로와 교과 탐구의 자연스러운 연결
후속 탐구 정렬됨·무작위·역순 데이터 비교, 비교·이동 횟수 측정 계획 기존 결과에서 새로운 연구문제를 도출함

특히 세특에서 가치가 큰 부분은 “Python으로 정렬 알고리즘을 구현했다” 는 사실 자체보다,

동일 데이터 사용 → 10회 반복 측정 → 평균 계산 → 성능 비교 → 실행시간 차이의 원인 분석 → 후속 조건 제안

까지 연결했다는 점입니다.

3. 탐구보고서 보완 포인트

현재 보고서만으로도 세특 반영 근거가 비교적 분명합니다.

실제값, 반복 측정, 비교조건, 계산, 성능평가, 코드 실행, 오차 분석이 모두 포함되어 있기 때문입니다.

다만 제출 전 확인하면 좋은 부분은

  1. 실제 Colab에서 만든 실행시간 비교 그래프를 보고서에 포함하기
  2. 핵심 Python 코드를 실제 실행 순서에 맞춰 첨부하기
  3. 가능하면 10회 개별 측정값도 원자료로 보관하기

특히 평균값만 남기기보다 1~10회의 개별 실행시간이 있으면 반복 측정을 실제 수행했다는 근거가 더 명확해집니다.

후속 탐구를 실제로 수행한다면 입력 데이터가 이미 정렬된 경우, 무작위인 경우, 역순인 경우 를 비교하거나, 코드에 비교 횟수와 이동 횟수 카운터 를 추가하는 방향이 가장 자연스럽습니다.

이는 현재 결과에서 발견한 “같은 O(n²) 정렬인데 실제 실행시간은 왜 다른가?” 라는 질문을 한 단계 더 깊게 탐구하는 방향입니다.
